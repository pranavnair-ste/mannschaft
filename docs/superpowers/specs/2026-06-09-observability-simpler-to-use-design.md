# Design: Make the observability dashboard simpler to use

**Date:** 2026-06-09
**Status:** Approved (brainstorming → spec)
**Branch (to create for implementation):** `feat/observability-dx`
**Relates to:** `docs/superpowers/specs/2026-06-05-combined-observability-design.md` (the approved fork-as-primary architecture), `docs/superpowers/plans/2026-06-07-observability-phase3.md` (the launcher/auth work this builds on).

> **Terminology:** the dashboard is the repo `pranavnair-ste/pi-agent-observability` (a fork of `disler/pi-agent-observability`). For git operations we still reference that repo, but in prose, CLI output, and user-facing docs it is **the observability dashboard** — never "the fork".

---

## 1. Problem

The observability stack is fully functional end-to-end (Phase 3, verified), but *using* it is painful for anyone who isn't the author. Three friction surfaces, all confirmed in code:

**Setup is a manual scavenger hunt and author-specific.**
- `DEFAULT_OBS_FORK_DIR = "~/Desktop/Personal/pi-agent-observability"` (`pi_harness/config.py:28`) won't exist on any other machine.
- The dashboard must be cloned by hand from `pranavnair-ste/...` (not upstream `disler`), then `bun install` — there is no setup command and the quickstart prereqs don't cover it.
- `bun` install isn't explained; the auth token is generated by hand (`openssl rand -hex 16`).
- `ms up` only works from the repo root because the UI process uses relative `cwd=Path("ui")` (`pi_harness/cli.py:313`); the doctor's `ui/node_modules` check has the same problem (`cli.py:371`).
- `PI_HARNESS_OBS_ENABLED` is misleadingly named: it only gates the Symphony deep-link button, **not** whether `up`/`observe` work — so you can "succeed" and still see no live events (the dashboard's SSE returns 401 because `OBS_DEV=1` minted an ephemeral token the deep-link doesn't know).

**Daily launch hides failures.**
- `Supervisor.wait_ready()` (`pi_harness/observability/supervisor.py`) times out **silently** — if the dashboard is slow to boot, the bridge starts tailing an unreachable server and the user just sees "no events", no error.
- The deep-link button is only on run-detail (`ui/app/runs/[runId]/page.tsx`), not the run list (`ui/app/page.tsx`).

**The dashboard's own UX has friction.**
- Empty `.env.sample` token → `server.ts` exits with a cryptic `Refusing to start with a default/weak OBS_AUTH_TOKEN` (no "add `OBS_DEV=1`" hint); three different start paths (`just obs` / `just all` / `bun run start`) behave differently.
- No-data landing shows only `◈ Select a session` — zero onboarding.
- The pool/tag filter is a free-text input with no indication when it's actively hiding data.
- Race/Swimlane require knowing raw session UUIDs; there's no "copy shareable link" button.
- Stale: inner `apps/observability/README.md` API table omits `/sessions/:id/stats`; `scripts/spawn-fleet.sh:5` still defaults to `devtoken` (now rejected by the hardened server).

## 2. Goals / Non-goals

**Goal (north star):** On a fresh mannschaft checkout, with only `bun` and `npm` pre-installed, `ms up` clones+pins the dashboard, provisions a token, boots all four processes, opens a live dashboard with **stable** deep-links, and reports loudly when a process didn't come up.

**In scope (all four, per 2026-06-09 brainstorming):** zero-to-running setup, reliable daily launch, dashboard UX, and distribution/portability.

**Non-goals:**
- The unified wall-clock-merged run timeline ("view 3") — still deferred, exists in neither tool.
- Publishing the dashboard as an npm package or Docker image (rejected; auto-clone chosen instead).
- Vendoring the dashboard into mannschaft (rejected; preserves the dashboard→`disler`-upstream PR workflow).
- Changing the bridge translation/seq invariants — those are correct and stay untouched.

## 3. Decisions (resolved during brainstorming)

| # | Decision | Choice |
|---|----------|--------|
| D1 | How the dashboard ships | **Auto-clone at a pinned ref.** Stays an independent repo; one pinned ref = reproducible; network needed on first run only. |
| D2 | Auth/enable model | **Auto-provision a persistent token** in `~/.pi-harness/keystore`, reused every run. `obs_enabled` repurposed to genuinely mean "observability on", auto-set by `ms up`. |
| D3 | Dashboard UX items | **All four:** empty-state onboarding, copy shareable-link button, clearer pool/tag filter, start-path & boot polish. |
| D4 | Default dashboard dir | Change from `~/Desktop/Personal/pi-agent-observability` → app-owned **`~/.pi-harness/obs-dashboard`**. Portable for everyone; the author's dev clone is used by setting `PI_HARNESS_OBS_FORK_DIR`. |
| D5 | Pin target | Create tag **`v0.3.0`** on the dashboard repo at current `main` (`ed4d7b3`) and pin to it. |
| D6 | Protect dev clones | Bootstrap only clones when the dir is **missing**. An existing dir is validated but its git state is never touched; re-pinning is opt-in (`ms setup-obs --update`). |

## 4. Architecture

Two repos. mannschaft (Python launcher + Next.js UI) and the observability dashboard (Bun server + static JS). The dashboard changes ship as a **separate PR** (remember `gh pr create -R pranavnair-ste/pi-agent-observability` — it otherwise resolves to the `disler` upstream remote).

### Component 1 — Dashboard bootstrap (auto-clone at pinned ref) · mannschaft

New module `pi_harness/observability/bootstrap.py`:

- `ensure_dashboard(cfg) -> Path`:
  - **Missing dir:** `git clone https://github.com/pranavnair-ste/pi-agent-observability <dir>`, then `git -C <dir> checkout <obs_fork_ref>`, then best-effort `bun install` in `<dir>` (D6, and "best-effort" because the server's only dep is `@types/bun` — a failed/again-noop install must not abort boot, only warn).
  - **Existing dir:** assert `<dir>/apps/observability/server.ts` exists; do **not** run any git command that mutates state. If `git -C <dir> rev-parse HEAD` ≠ resolved pinned ref, log a one-line warning (`dashboard at <dir> is at <sha>, pinned ref is <ref>; run 'ms setup-obs --update' to re-pin`). Never auto-checkout (D6).
  - All subprocess calls go through a small helper that raises a typed `BootstrapError` with the captured stderr so `doctor`/`up` can print actionable messages.
- New config field on `Config` (`pi_harness/config.py`): `obs_fork_ref: str` from env `PI_HARNESS_OBS_FORK_REF`, default `"v0.3.0"` (D5).
- Change `DEFAULT_OBS_FORK_DIR` to `~/.pi-harness/obs-dashboard` (D4). `obs_fork_dir` env var name (`PI_HARNESS_OBS_FORK_DIR`) is kept for back-compat.

### Component 2 — One-command setup + persistent token · mannschaft

- `ensure_obs_token(cfg) -> str` (in `bootstrap.py` or a small `obs_secrets.py`):
  - If `OBS_AUTH_TOKEN` is already set (env or keystore) and non-weak → return it.
  - Else generate `secrets.token_hex(16)`, append `OBS_AUTH_TOKEN=<tok>` to `~/.pi-harness/keystore` (create with `0o600` if absent; the keystore is already loaded by `load_config()` with `override=True`), and return it. Idempotent — never overwrites an existing token.
- `obs_enabled` repurpose:
  - `ms up` and `ms setup-obs` persist `PI_HARNESS_OBS_ENABLED=1` to the keystore (alongside the token) so subsequent `load_config()` calls see observability as enabled and the Symphony deep-link button (`/observability/link` `enabled` field) appears.
  - The token is provisioned **before** the existing `config.py:122-126` "enabled requires token" check is hit, so that check never errors in the happy path. (The check stays as a guard for the misconfigured case.)
- **Run-from-anywhere:** introduce a `repo_root()` helper (anchor on the package location, e.g. `Path(__file__).resolve().parents[1]`) and use it for the UI process `cwd` (`cli.py:313`) and the doctor `node_modules` check (`cli.py:371`). The bridge and api already launch via `sys.executable -m ...` so they're unaffected.
- New/extended CLI: `ms setup-obs` (clone+token+enable in one shot; `--update` re-pins an existing dir). `ms doctor` reuses `ensure_dashboard`'s validation and prints the GitHub clone URL when the dir is missing instead of a bare ✗.

### Component 3 — Launch reliability · mannschaft + ui

- `Supervisor.wait_ready()` returns a per-proc readiness report (`dict[name -> bool]` or a small dataclass) instead of nothing. `ms up` prints which procs came up and, on any not-ready health-checked proc, a one-line hint (e.g. `fork didn't answer on :43190 within Ns — check bun / OBS_AUTH_TOKEN`). New `ms up --strict` aborts (non-zero exit) when a health-checked proc isn't ready; default stays non-aborting so the bridge can keep waiting.
- Bridge: on the first connection failure to the dashboard, `follow_runs` logs one clear `dashboard unreachable at <url> — retrying; events will flow once it's up` warning rather than per-run spam (track a "already warned" flag, reset on success).
- **Deep-link on the run list:** `ui/app/page.tsx` gains a header "Open live dashboard ↗" link, resolved via the existing `api.obsLink` (`ui/lib/api.ts:79-82`) against a sentinel/empty run so it points at the dashboard root race view; only rendered when `enabled`. (Per-row deep-links are optional and out of the core.)
- `ms up --open/--no-open` (default open): `webbrowser.open(deep_link)` after `wait_ready` succeeds.

### Component 4 — Dashboard UX · dashboard repo (separate PR)

1. **Empty-state onboarding** (`apps/observability/public/app.js`): when `/sessions` returns zero globally, the select panes render a first-run card — the exact command to produce events (`ms launch <spec>` or `just agent`), a note that the dashboard streams live, and a docs link. When sessions exist but the active pool/tag filter hides them all, render `N sessions hidden by filter — clear it` with a clear-filter action.
2. **Copy shareable-link button** (header, near the view toggle): copies `location.href` (already encodes view + lanes + filters + token). Tooltip notes the link includes the access token.
3. **Clearer pool/tag filter:** populate a pool dropdown client-side from distinct `pool` values in the already-loaded `/sessions` response (no server change) and render a prominent active-filter chip (`pool: run-abc ✕`) whenever a filter is set.
4. **Start-path & boot polish:** `server.ts` refuse-to-start message becomes actionable (`Set OBS_AUTH_TOKEN=<strong value> or OBS_DEV=1 for local dev`); README documents a single primary start path (`ms up` from mannschaft) with `just obs` as the standalone alternative; fix the stale inner `apps/observability/README.md` API table (add `GET /sessions/:id/stats`) and `scripts/spawn-fleet.sh:5` `devtoken` default.

## 5. Phasing

- **P1 — keystone + setup (mannschaft):** Component 1 (bootstrap/auto-clone), Component 2 (token, `obs_enabled` repurpose, run-from-anywhere, `ms setup-obs`). Outcome: `ms up` works on a fresh machine.
- **P2 — reliability (mannschaft + ui):** Component 3 (`wait_ready` surfacing, bridge warning, run-list deep-link, `--open`).
- **P3 — dashboard UX (dashboard repo, separate PR):** Component 4's four items.

## 6. Testing

- **mannschaft (`pytest -m "not smoke"` — smoke launches a real ClawTeam team that git-commits to the branch, hazard):**
  - `bootstrap`: mock `git`/`bun` subprocess — missing dir → clone+checkout+install invoked; existing dir → no state-mutating git call, warning on ref mismatch; `BootstrapError` carries stderr.
  - `ensure_obs_token`: writes keystore with `0o600`, idempotent (existing token preserved), generates strong token when absent.
  - config: new `obs_fork_ref`, changed default dir, `obs_enabled` persisted+read.
  - `Supervisor.wait_ready`: returns per-proc readiness; `ms up` reports not-ready procs; `--strict` exits non-zero.
  - deep-link route `enabled`-state; run-list link renders only when enabled.
  - UI: `tsc` clean + the existing offline Playwright harness (`tests/ui/` + `_fixtures` backend + `page.route` stubs) for the run-list link.
- **dashboard repo:** extend `scripts/smoke-server.sh`; add JS-level checks for the empty-state and pool-dropdown where feasible; manual verify via `ms up`.

## 7. Risks & mitigations

- **Clobbering a dev clone:** bootstrap clones only when the dir is missing; re-pin is opt-in (D6).
- **Default-dir change** (D4): the author's existing dev clone is only used if `PI_HARNESS_OBS_FORK_DIR` points at it — documented in the quickstart and `ms setup-obs` output.
- **Token in deep-link URL + clipboard:** acceptable for loopback-only binding; surfaced in the copy-link tooltip.
- **No tag on the dashboard repo yet:** create `v0.3.0` at `ed4d7b3` as a first implementation step (D5).
- **`bun install` may be a no-op** (only `@types/bun`): best-effort, warn-don't-fail.
- **Fork PR remote footgun:** `gh pr create -R pranavnair-ste/pi-agent-observability` (otherwise targets `disler`).
